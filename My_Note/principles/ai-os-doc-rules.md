# AI OS 문서 운영 규칙

## 0. 이 문서의 목적

이 문서는 AI OS 안에서 TODO, Decision, My Notes, LLM Wiki를 어떻게 구분하고 연결할지 정리한 운영 규칙이다.

목적은 문서를 많이 만드는 것이 아니다.  
문서가 쌓여도 다시 찾을 수 있고, AI가 읽어도 목적을 오해하지 않으며, 내가 다시 봐도 핵심을 빠르게 이해할 수 있게 만드는 것이다.

---

## 1. 핵심 원칙

### 1.1 TODO는 짧게 유지한다

TODO는 앞으로 실행할 항목만 관리한다.

TODO에는 긴 설명, 고민, 판단 근거, 회고를 넣지 않는다.  
설명이 길어지면 TODO가 아니라 My Notes나 Decision으로 보낸다.

TODO의 기준:

- 체크박스로 완료 처리할 수 있으면 TODO다.
    
- 지금 또는 가까운 시점에 실행할 수 있어야 한다.
    
- 실행 문장으로 쓴다.
    
- 가능한 짧게 쓴다.
    

예시:

```md
- [ ] docs/INDEX.md에 guide/source/feature/graph 링크 추가하기
- [ ] 2026-07 Decisions 문서에 상태 필드 추가하기
```

---

### 1.2 Decision은 판단의 맥락을 보존한다

Decision은 해야 할 일이 아니라, 이미 정한 판단과 그 이유를 기록한다.

Decision의 기준:

- “왜 이렇게 하기로 했는가?”를 설명해야 하면 Decision이다.
    
- 나중에 AI가 구조를 이해하는 데 필요한 판단이면 Decision이다.
    
- 결정의 영향 범위와 다시 검토할 조건을 함께 남긴다.
    

Decision에는 다음 항목을 포함한다.

```md
### 결정
### 이유
### 영향
### 검토 조건
### 관련 문서
```

---

### 1.3 My Notes는 AI OS의 중심 기억이다

My Notes는 완료된 작업에서 얻은 경험, 판단, 고찰, 배움을 축적한다.

My Notes는 TODO list가 아니다.  
앞으로 할 일을 관리하는 문서가 아니라, 내가 무엇을 했고 무엇을 배웠는지 남기는 문서다.

My Notes에는 다음이 들어간다.

- 작업 결과
    
- 진행 과정
    
- 판단과 고민
    
- 좋았던 점
    
- 불편했던 점
    
- 새롭게 배운 점
    
- 다음에 적용할 원칙
    
- AI / Codex 활용에 대한 평가
    

---

### 1.4 LLM Wiki는 재사용 가능한 지식만 저장한다

LLM Wiki는 외부 지식과 일반화 가능한 원칙을 저장한다.

LLM Wiki에는 개인적 감정, 작업 당시의 맥락, 일기식 기록을 넣지 않는다.  
그런 내용은 My Notes에 남긴다.

LLM Wiki에 넣을 수 있는 내용:

- 재사용 가능한 문서 운영 원칙
    
- 프롬프트 작성 규칙
    
- 도구 사용법
    
- 프로젝트 구조 설명
    
- 반복 적용 가능한 판단 기준
    
- 외부 문서나 자료를 정리한 내용
    

---

## 2. 문서별 역할

|문서 유형|역할|질문|길이|
|---|---|---|---|
|TODO|실행 큐|무엇을 해야 하는가?|짧게|
|Decision|판단 기록|왜 그렇게 하기로 했는가?|중간|
|My Notes|경험과 고찰|무엇을 했고 무엇을 배웠는가?|깊게|
|LLM Wiki|재사용 지식|다음에도 쓸 수 있는 원칙인가?|정리된 형태|

---

## 3. 문서 분류 기준

### 3.1 TODO로 둘 것

아래 조건에 해당하면 TODO로 둔다.

- 체크박스로 완료할 수 있다.
    
- 실행 단위가 명확하다.
    
- 지금 또는 가까운 시점에 처리할 일이다.
    
- 긴 설명 없이도 이해된다.
    

예시:

```md
- [ ] My Notes index 2026-07.md 생성하기
- [ ] docs/guide/05-decisions.md에 최신 결정 요약 추가하기
```

---

### 3.2 Decision으로 둘 것

아래 조건에 해당하면 Decision으로 둔다.

- 이미 방향을 정했다.
    
- 나중에 “왜 이렇게 했는가?”를 설명해야 한다.
    
- 여러 문서나 작업 방식에 영향을 준다.
    
- 시간이 지나면 다시 검토할 수 있다.
    

예시:

```md
Obsidian과 LLM Wiki 관리는 docs/ 중심으로 운영한다.
루트 문서는 docs/INDEX.md에서 링크로 참조한다.
```

---

### 3.3 My Notes로 둘 것

아래 조건에 해당하면 My Notes로 둔다.

- 작업이 끝난 뒤의 고찰이다.
    
- 개인적 경험과 판단이 포함된다.
    
- 무엇을 느꼈고 배웠는지가 중요하다.
    
- 다음에 비슷한 작업을 할 때 참고하고 싶다.
    

예시:

```md
TODO라는 이름 때문에 문서 목적이 실행 목록 중심으로 왜곡되었다.
앞으로는 문서 이름을 정하기 전에 “이 문서가 무엇이 아닌가”를 먼저 정의한다.
```

---

### 3.4 LLM Wiki로 둘 것

아래 조건에 해당하면 LLM Wiki로 둔다.

- 개인 맥락 없이도 재사용 가능하다.
    
- 다른 프로젝트에도 적용할 수 있다.
    
- AI에게 반복적으로 알려줘야 하는 지식이다.
    
- 외부 지식을 정리한 내용이다.
    

예시:

```md
TODO는 실행 큐, Decision은 판단 기록, My Notes는 경험 축적, LLM Wiki는 재사용 지식으로 분리한다.
```

---

## 4. 읽기 부담을 줄이는 규칙

My Notes는 길어질 수 있다.  
하지만 매번 전체를 다시 읽는 구조로 만들면 실패한다.

따라서 모든 My Notes 기록에는 맨 위에 다음 섹션을 둔다.

```md
## 0. 다시 읽을 때 이것만 보기

### 한 줄 요약
-

### 핵심 판단 3개
1.
2.
3.

### 다음에 적용할 원칙 3개
1.
2.
3.

### 다시 볼 필요가 있는 경우
-
```

상세 기록은 아래에 보존한다.  
자주 읽는 것은 상세 기록이 아니라 요약, 인덱스, 원칙 문서다.

## 5. My Notes 운영 구조

My Note는 다음 3층 구조를 기준으로 관리한다.

```md
My_Note/
├─ index/
│  └─ 2026-07.md
│
├─ records/
│  └─ YYYY/
│     └─ MM/
│        └─ YYYY-MM-DD_제목.md
│
└─ principles/
   └─ ai-os-doc-rules.md
```

역할은 다음과 같다.

```md
records/
- 상세 작업 완료 기록
- 길어도 된다
- 매번 다 읽지 않는다

index/
- 월간 요약
- 자주 읽는 곳
- 핵심만 남긴다

principles/
- 반복 적용할 원칙
- 짧고 안정적으로 유지한다
```

`records/`와 `principles/`는 기본 영역이다.
`index/`는 기록이 늘어나 월간 요약이 필요해질 때 생성하는 선택 영역이며, 빈 구조를 유지하기 위해 미리 만들지 않는다.

## 6. 작업 흐름

### 6.1 작업 전

1. 실제로 할 일만 TODO에 짧게 적는다.
    
2. 작업의 목적이나 고민이 길면 TODO에 쓰지 않는다.
    
3. 중요한 방향 결정이면 Decision으로 기록한다.
    

---

### 6.2 작업 중

1. TODO는 상태 관리만 한다.
    
2. 진행 중 생긴 판단과 고민은 임시 메모로 둔다.
    
3. AI나 Codex가 관리하더라도 문서 목적은 사람이 정한다.
    

---

### 6.3 작업 완료 후

1. TODO를 완료 처리한다.
    
2. 의미 있는 작업이면 My Notes record를 작성한다.
    
3. record 맨 위에 “다시 읽을 때 이것만 보기”를 작성한다.
    
4. 일반화 가능한 내용은 LLM Wiki 후보로 분리한다.
    
5. 월간 index에 핵심 요약만 추가한다.
    
6. 반복 적용할 규칙은 principles 문서에 반영한다.
    

---

## 7. AI에게 문서 정리를 맡길 때의 규칙

AI에게 문서를 맡길 때는 먼저 문서의 정체성을 알려준다.

예시:

```md
이 문서는 TODO list가 아니다.
작업 완료 후 작성하는 My Notes 기록이다.
해야 할 일 목록을 만들지 말고, 결과·판단·고찰·배운 점·다음에 적용할 원칙을 중심으로 정리해라.
TODO, Decision, My Notes, LLM Wiki를 섞지 말고 각각 분리해라.
```

AI에게 맡길 때 반드시 요구할 것:

- 문서 유형 구분
    
- 요약 섹션 작성
    
- 긴 기록과 짧은 요약 분리
    
- TODO 자동 생성 금지
    
- My Notes 후속 메모를 자동으로 TODO로 승격하지 않기
    
- LLM Wiki 후보와 My Notes 내용을 분리하기
    

---

## 8. 금지할 것

아래 방식은 피한다.

- TODO에 긴 고민을 적는 것
    
- Decision을 체크박스로 관리하는 것
    
- My Notes를 항상 처음부터 끝까지 다시 읽어야 하는 구조로 만드는 것
    
- LLM Wiki에 외부 자료만 쌓고 목적을 정하지 않는 것
    
- My Notes에서 나온 후속 아이디어를 전부 TODO로 올리는 것
    
- 문서 이름만 보고 목적을 정하는 것
    
- AI가 만든 문서를 사람이 검토하지 않는 것
    

---

## 9. 최종 원칙

```md
TODO는 짧게.
Decision은 이유와 함께.
My Notes는 깊게.
LLM Wiki는 재사용 가능하게.
Index는 다시 읽기 쉽게.
Principles는 반복 적용 가능하게.
```

AI OS의 중심은 LLM Wiki가 아니라 My Notes다.  
LLM Wiki는 외부 지식과 일반화 가능한 원칙을 저장하고, My Notes는 나의 경험과 판단을 축적한다.

좋은 AI OS는 문서를 많이 가진 시스템이 아니라,  
필요한 순간에 내 판단과 원칙을 다시 꺼낼 수 있는 시스템이다.
