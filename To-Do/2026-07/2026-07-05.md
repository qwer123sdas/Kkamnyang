# 3. LLM Wiki 운영 규칙 정리


> 진행한 내용 요약

## 판단

- `docs/guide/08-llm-wiki-guide.md`와 `docs/guide/10-llm-wiki-operations.md`는 역할이 겹친다.
- 둘 다 AI Agent가 프로젝트 문서를 어떻게 읽고 유지해야 하는지 다루는 문서다.
- 운영 규칙은 단일 진입점이어야 하므로 `08-llm-wiki-guide.md` 하나로 합치는 것이 맞다.

## 정리한 방향

- `10-llm-wiki-operations.md`의 내용을 `08-llm-wiki-guide.md`에 병합한다.
- `docs/INDEX.md`에는 LLM Wiki 관련 링크를 `08-llm-wiki-guide` 하나만 남긴다.
- `10-llm-wiki-operations.md`는 중복 문서이므로 제거한다.

## wiki/raw/archive 대체 방식

`LLM-Wiki.md`의 범용 구조를 그대로 만들지 않고, KKamyang의 기존 문서 구조로 대체한다.

```text
LLM Wiki 개념       KKamyang 대체 위치
-----------------   -----------------------------------------
wiki/               docs/
raw/                docs/source/ + 루트 기준 문서 + 코드
archive/            docs/archive-or-legacy/
index.md            docs/INDEX.md
log.md              HANDOFF.md + docs/HANDOFF.md + docs/task/
schema/rules        AGENTS.md + docs/guide/
```

## 이유

- 새 `wiki/` 폴더를 만들면 기존 `docs/`와 역할이 중복된다.
- 새 `raw/` 폴더를 만들면 `docs/source/`와 루트 기준 문서의 역할이 흐려진다.
- 새 `archive/` 폴더를 만들면 이미 존재하는 `docs/archive-or-legacy/`와 중복된다.
- 별도 `log.md`를 만들면 HANDOFF와 Task 문서에 기록해야 하는 작업 이력이 분산된다.

## 최종 운영 원칙

- `docs/`를 프로젝트 Wiki로 간주한다.
- 기준 문서는 `docs/source/`와 루트 문서를 우선한다.
- 오래된 문서는 `docs/archive-or-legacy/`에 보존한다.
- 작업 흐름과 결과는 `HANDOFF.md`, `docs/HANDOFF.md`, `docs/task/`에 기록한다.
- LLM Wiki 운영 규칙은 `docs/guide/08-llm-wiki-guide.md` 하나를 기준으로 삼는다.
- `LLM-Wiki.md`는 참고용 아이디어 문서로만 사용하고, 구조를 그대로 구현하지 않는다.
