# Frontend Backend Contract

## Purpose

Frontend와 backend가 공유해야 하는 인증, 공통 응답 처리, 환경변수, 계층 경계와 UI 상태 기준을 한 문서에 고정한다.

이 문서는 전체 엔드포인트 목록이나 엔드포인트별 필드를 소유하지 않는다.
상세 API 계약은 [[docs/source/api-spec]]을 기준으로 하고, 이 문서는 frontend 작업자가 계층 간 통합 규칙을 확인하기 쉽게 정리한다.

## Base URL

```text
/api/v1
```

Frontend는 `EXPO_PUBLIC_API_BASE_URL`을 사용해 backend base URL을 결정한다.

Android 실기기 QA에서는 `127.0.0.1` 또는 `localhost`를 사용하지 않는다. PC의 IPv4 주소를 사용한다.

## Environment Variables

Frontend:

```text
EXPO_PUBLIC_SUPABASE_URL
EXPO_PUBLIC_SUPABASE_ANON_KEY
EXPO_PUBLIC_API_BASE_URL
EXPO_PUBLIC_GOOGLE_MAPS_API_KEY
```

Backend:

```text
SUPABASE_URL
SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
```

Security:

```text
1. 실제 값은 문서, 로그, 응답에 출력하지 않는다.
2. 값 확인은 SET/NOT_SET만 기록한다.
3. SUPABASE_SERVICE_ROLE_KEY는 frontend 또는 Expo 환경변수로 전달하지 않는다.
4. EXPO_PUBLIC_* 값도 신뢰 경계 밖 데이터로 취급한다.
```

## Authorization

Frontend는 Supabase session에서 access_token을 가져와 backend API 호출 시 전달한다.

```http
Authorization: Bearer {access_token}
```

Backend는 요청 body의 user_id를 신뢰하지 않는다.

```text
1. Bearer token을 검증한다.
2. Supabase Auth user.id를 서버에서 얻는다.
3. 해당 user.id로 users row를 조회하거나 생성한다.
```

## Common Response Shape

Success:

```json
{
  "success": true,
  "data": {},
  "message": null
}
```

Error:

```json
{
  "success": false,
  "data": null,
  "message": "error message",
  "error_code": "ERROR_CODE"
}
```

Frontend는 API 응답 구조를 화면별로 임의 해석하지 않는다. 공통 `apiClient`를 통해 처리한다.

## Layering Rule

Frontend 호출 흐름:

```text
Screen
-> Hook
-> Service
-> apiClient
-> Backend API
```

Rules:

```text
1. Screen에서 직접 fetch를 호출하지 않는다.
2. Screen에서 Supabase session을 반복 구독하지 않는다.
3. action/load 시점에 필요한 경우 authService.getSession()을 1회 사용한다.
4. Detail/Profile/MyRoutes/Bookmarks hook은 useAuth를 구독하지 않는다.
5. API endpoint path는 service 계층에 둔다.
```

## Core Endpoints

이 절은 frontend 통합의 최소 핵심 흐름만 나열하며 전체 API 목록을 의미하지 않는다.

### Health

```http
GET /api/v1/health
```

Purpose:

```text
Backend availability check.
Android physical device network check.
```

### Users Me

```http
GET /api/v1/users/me
```

Authorization:

```text
Required.
Bearer Supabase access_token.
```

Frontend usage:

```text
Profile
Auth post-login user sync
Identity display
```

Policy:

```text
1. user_id is not sent from frontend.
2. Social login_id is generated by backend.
3. Social login_id format is social_ + Supabase Auth UUID hex first 23 chars.
4. email is stored only in email column.
5. created_by and updated_by use login_id, not email.
```

### Activity Start

```http
POST /api/v1/activities/start
```

Authorization:

```text
Required.
```

Policy:

```text
1. MVP activity_type is RUN.
2. API response shape must not be changed for UI-only metrics.
3. Record UI starts live Duration after STARTED state.
```

### Activity Finish

```http
POST /api/v1/activities/{activity_id}/finish
```

Authorization:

```text
Required.
```

Policy:

```text
1. Finish is allowed when GPS point count is at least 1.
2. If there is only 1 GPS point, duplicate the first point as stationary end point.
3. GPS noise rules stay active: ignore movement under 5m and speed over 40km/h.
4. Finish creates route data and links it to the activity.
```

## Frontend State Requirements

Each API-backed screen should handle:

```text
loading
empty
error
success
unauthenticated
```

Record-specific states:

```text
location permission pending
location permission denied
map key missing fallback
record idle
record started
record finishing
```

## Android Physical Device Notes

Backend must listen on all interfaces:

```powershell
python -m uvicorn app.main:app --reload --app-dir backend --host 0.0.0.0 --port 8000
```

Frontend `EXPO_PUBLIC_API_BASE_URL` must point to the PC IPv4 address and backend port.

Health check from Android browser:

```text
http://PC-IPv4:8000/api/v1/health
```

## Error Handling Direction

Frontend should map failures to stable UI states:

```text
401 or missing session -> logged-out or retry login state
403 -> permission or authorization state
404 -> missing resource state
500 -> server error state
network failure -> retryable network state
map key missing -> Record map fallback
location permission denied -> permission denied state
```

Logs must not include secret values or access tokens.

## Change Control

Requires separate task/document approval:

```text
1. API response shape change
2. DB schema change
3. Router structure change
4. State management library change
5. New library addition
6. Health metrics implementation
7. RIDE or HIKE support
```
